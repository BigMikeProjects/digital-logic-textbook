Why a synchronous circuit cannot just ignore it
  • How long contacts bounce depends on the switch: often a few milliseconds, sometimes much longer. Designers wait out a safe window, commonly 10–20 ms.
  • A 100 MHz clock sees 100,000 clocks per millisecond. Every bounce is thousands of clocks wide: to the logic it is a real level, not a glitch.
  • So the circuit has to be designed to wait it out: accept a new level only after it has held steady for N clocks.

Why it works

                        
C only reaches N − 1 if S and Q disagree for N clocks in a row in WAIT. Every bounce makes them agree again, which sends the machine back to IDLE, and IDLE sets C back to 0.

                        
This graphic uses N = 4 and 8 so the timing diagram fits on a page. A real button needs N in the hundreds of thousands: the same circuit with a wider C.

Definitions
D or Esc closes

            

                
Bounce
A mechanical switch closes and opens several times after a press or release; how long depends on the switch. A counter wired to it sees several presses.

                
Synchronizer
Two D flip-flops in series. The first may go metastable when the input changes inside its setup window; the second samples it a full clock later, after it has settled. See Synchronizers.

                
btn, S, Q
btn is the raw button. S is the button after the synchronizer: it still bounces, but only changes on clock edges. Q is the clean, debounced output.

                
Register C
The count. An adder makes C + 1 and a mux picks 0 or C + 1: the mux picks 0 when clr = 1 (IDLE, LOAD) and C + 1 when clr = 0 (WAIT). The same register, adder and comparator pattern appears in the Timer Circuit.

                
Control signals
Controller → datapath. clr = 1 sets C to 0, in IDLE and in LOAD, so C only counts in WAIT. ldQ copies S into Q, in LOAD.

                
Status signals
Datapath → controller, from two comparators. diff = 1 when S and Q differ. tc = 1 when C = N − 1.

                
FSMD
Finite state machine with datapath. Here three states, named for what the debouncer believes: IDLE (S agrees with Q), WAIT (they disagree: count it), LOAD (believe it). See FSMD - Finite State Machines with Datapaths.

                
N, the window
How many clocks in a row S and Q must disagree before Q changes. N = window × fclk: a 10 ms window at 100 MHz is a million. C must be able to hold N, so it needs ⌈log2(N + 1)⌉ bits: 20 for a million.

                
Latency
From S first differing from Q to Q changing: 1 clock in IDLE, N in WAIT, 1 in LOAD. At N = 4 the trace shows it: S differs from Q from cycle 10, WAIT runs 11–14, LOAD at 15, Q changes at 16.
