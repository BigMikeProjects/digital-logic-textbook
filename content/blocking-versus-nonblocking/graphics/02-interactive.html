Blocking =sees the line above
Non-blocking <=reads the values from before

With =, q2 reads the q1 that was just written, and q3 reads the q2 that was just written. d reaches all three in one edge. That is not a shift register: it is three flip-flops all copying d.

With <=, every line reads the value from before the edge, and all three update together, the way real flip-flops sharing one clock all capture at the same instant.

Both sides start at 0 0 0. From edge 2 on, each side starts from its own last result (the small was in each flip-flop), because = and <= built two different circuits.

A note on always @(*)
With @(*) the simulator also watches t1 and t2, because the block reads them. When t1 changes the block runs again, and again when t2 changes, until nothing changes. It all happens in the same instant, so the waveform shows the right y. The simulator covers for the stale values; the code still does not describe the gates. Use =.

The rule
<= in clocked blocks only = in combinational blocks only
never mix both in one block

The hardware decides which operator is right, not style. The same three-line shape needs old values in a shift register and new values in a gate chain.

Registers in Verilog is the <= half on its own. FSM Coding Template uses exactly this split: one posedge block with <= for the state register, and @(*) blocks with = for the next-state and output logic.
