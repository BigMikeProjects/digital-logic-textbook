The rule: an arc you don't draw is a term you don't write. A diagram that leaves loop-backs implicit ("otherwise, stay put") reads fine, and the binary method survives it — the state table fills the gap. One-hot has no state table: the diagram is the source. So before writing a single D, check every state — for each input value, does an arc leave it? If not, draw the loop-back first.

Reset — the one thing binary got for freeand the one gate that repairs it
0000 is not a state. Binary's all-zeros code was S0, so clearing the flip-flops was the reset. Clear a one-hot register and there is no 1 left to pass along: every D reads 0, and the machine is stuck for good. One answer is a reset that loads 0001. The other is one more gate — let 0000 itself lead to the start state on the next clock:
Binary wins on flip-flops; one-hot wins on design effort and on logic depth, and the gap grows with the machine: a 20-state controller is 5 flip-flops with five 5-variable K-maps in binary, or 20 flip-flops with twenty one-line equations in one-hot. Which one a real design uses depends on what flip-flops cost in the chip it is built on — a question for later in the course.
