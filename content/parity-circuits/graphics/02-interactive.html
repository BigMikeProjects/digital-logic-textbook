ones in the word: 0 even
The parity bit is chosen so the whole 5-bit word comes out with an even number of 1s. Toggle the data and watch P follow.
Parity is the cheapest error detection there is: add one bit so the number of 1s in the word comes out even — or odd, as long as both ends agree.
Parity detects, it does not correct — and it only detects an odd number of flipped bits. One flipped bit is always caught. Two flipped bits are always missed: the count returns to even and the word looks perfect. Beat 3 lets you do it yourself.
The generator and the checker are the same circuit. The checker is this tree one input wider, taking all five received bits: E = R4 ⊕ R3 ⊕ R2 ⊕ R1 ⊕ R0.
Chain — 3 gates deep
Depth grows linearly: n−1 gates from input to output. A 32-bit chain is 31 gate delays deep.
Balanced tree — 2 gates deep
Same gates, same function, shorter critical path: depth ⌈log₂n⌉. A 32-bit tree is 5 deep, not 31. Logic and timing are separate concerns.
Memory parity
One extra bit per byte. A parity error raises an exception instead of letting corrupt data through unnoticed.
Serial links
The parity bit in 8N1 / 8E1 framing. If you have ever configured a serial port you have chosen one already.
Bus checking
A parity bit carried alongside an address or data bus, checked at the far end of the interconnect.

Where it runs out
One bit can detect but never locate an error. Correcting one needs several check bits (Hamming); catching bursts reliably needs a CRC.

This block's Verilog idiom: ^ as a reduction — one operator, any width
The generator and the checker
module par_gen (input [3:0] d, output p); assign p = ^d; // even parity: 1 when d holds an odd count endmodule module par_chk (input [4:0] w, output e); assign e = ^w; // 1 => odd count => corrupt endmodule
^d XORs every bit of d together — the whole tree from beat 2, in one operator. Widen the bus and the operator does not change, and the synthesiser picks the log-depth shape for you.
!
Even parity's generator is ^d, not ~^d. Read ^d as "is the count odd?" — that is exactly the bit you must append to make it even. The naming feels inverted and is a reliable source of sign errors.
Parity is the first rung on a ladder — detect 1, and no more
One check bit buys one fact: the count is wrong. It cannot say which bit, and two flipped bits cancel and slip past. Spend more check bits and you buy more — first the location of the error, then the ability to repair it.
CORRECTS ONE BIT
Hamming code
Several parity checks over overlapping subsets of the bits. The pattern of which checks fail spells out the binary index of the broken bit, so you can flip it back. Hamming(7,4) protects 4 data bits with 3 check bits.
IN THE MACHINE YOU USE
ECC memory
Server DRAM carries 8 check bits per 64 data bits. That is extended Hamming — SECDED: single error corrected, double error detected. The same idea as beat 3's memory parity, one rung up.
BURSTS, NOT SINGLE BITS
CRC
Treats the message as the coefficients of a polynomial and divides by a fixed generator; the remainder travels along. Very strong on bursts of adjacent errors. Every Ethernet frame ends in a CRC-32.
SYMBOLS, NOT BITS
Reed–Solomon
Works on whole symbols, so one correction repairs a run of damaged bits. It is why a scratched CD still plays, why a torn QR code still scans, and how deep-space probes get data home.
!
The unifying idea is distance: how many bits must flip to turn one legal codeword into another. Parity has distance 2 — enough to notice one flip. Hamming has distance 3, which is enough to identify it. Buying correction always means buying distance, and distance is paid for in check bits.
Beyond these: LDPC and turbo codes carry 5G, Wi-Fi and SSDs, and get close to the theoretical limit Claude Shannon proved in 1948. None of it changes what parity is — it changes how much you are willing to spend.
