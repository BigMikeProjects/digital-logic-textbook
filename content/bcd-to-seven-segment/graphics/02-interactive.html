Four input bits, seven output bits. The block turns a binary-coded digit into the pattern of lit segments that draws it — the first block whose output is a picture rather than a number.
Glyph convention: 6 keeps segment a, 9 keeps segment d — the set that extends cleanly to hex A–F later (drop 6’s segment a and it becomes identical to a lowercase b).
BCD uses only 0–9, so inputs 1010 through 1111 never occur and every output is a don't-care on those six rows. That is not a footnote — it is the whole reason beat 2's equations are as small as they are.
Common cathode shares ground and wants active-high drivers. Common anode shares V+ and wants every output complemented — the 7447 is that part. Beat 1’s toggle shows the drive levels flip while the glyph stays put.
Each segment is an LED and needs a current-limiting resistor. This is where the logic meets a real load.

Multiplexed digits
One shared set of segment drivers, with a demux enabling one digit at a time — fast enough that persistence of vision shows them all lit at once.
Catalogue parts
The 7447 (active-low, common anode) and 7448 (active-high, common cathode). You will meet them in a lab and on a datasheet.
What is actually done
Nobody hand-minimises seven K-maps in industry — the pattern is a lookup table and the synthesiser does the reduction.
So why learn the minimisation? Because this is the clearest multi-output design exercise available: one shared set of inputs, seven independent functions, and six don't-care rows that visibly shrink the result. The technique is the lesson; the seven equations are not load-bearing in a modern flow, and it is worth being straight about that.
This block's Verilog idiom: case with a 7-bit literal per digit — the truth table, transcribed
How this block is actually written
module bcd7seg (input [3:0] n, output reg [6:0] seg); // {a,b,c,d,e,f,g} always @(*) begin case (n) 4'd0: seg = 7'b1111110; // 0x7E 4'd1: seg = 7'b0110000; // 0x30 4'd2: seg = 7'b1101101; // 0x6D 4'd3: seg = 7'b1111001; // 0x79 4'd4: seg = 7'b0110011; // 0x33 4'd5: seg = 7'b1011011; // 0x5B 4'd6: seg = 7'b1011111; // 0x5F 4'd7: seg = 7'b1110000; // 0x70 4'd8: seg = 7'b1111111; // 0x7F 4'd9: seg = 7'b1111011; // 0x7B default: seg = 7'b0000000; // 0x00 — blank endcase end endmodule
The same circuit, one segment at a time
// segment e, minimised with 10-15 as don't-cares assign e = (C & ~D) | (~B & ~D); // ...and the other six, from beat 2 assign c = D | ~C | B; assign b = (~C & ~D) | (C & D) | ~B;
Two altitudes, one circuit. The case is what you write; the equations are what the tool builds.
★
“Don't care” and default: are not the same commitment. The K-map don't-cares let codes 10–15 emit whatever is cheapest — garbage glyphs. default: seg = 7'b0000000; is a decision to blank the display instead. Same six rows, different circuits.
!
The default is also what covers 10–15 and prevents an inferred latch — a case on a 4-bit input with only ten arms is incompletely specified without it.
!
The bit order in {a,b,c,d,e,f,g} is a convention that must be stated in a comment, or the literals are unreadable. Getting it backwards is a silent and maddening bug.
