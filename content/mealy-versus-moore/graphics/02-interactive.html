Moorethe output logic reads the state, and nothing else
outputP = f(state)
The output is a property of where you are. It can only change when the register does — on a clock edge — so it is always a whole number of clocks wide and it cannot glitch. Paying for that costs a state and a clock of delay.
Mealythe same three boxes, plus one path — the input reaches the output logic too
outputP = f(state, L)
The output is a property of where you are and what is arriving. It can change the moment the input does, without waiting for an edge — which is both the whole advantage and the whole catch. Everything on the next three beats follows from this one path.
Moore — three statesP is written inside the bubbles
A whole state, PULSE, exists only to make P high for one clock. The arcs carry only the input.

PayoffOne clock sooner, one state fewer
L rises during a cycle and Mealy's P rises with it, through one AND gate; Moore's P waits for the edge that ends the cycle. Over any input stream P_mealy[t] = P_moore[t+1] — exactly one clock earlier. And Mealy does it with two states and one flip-flop, where Moore needs three states and two: PULSE is gone.
TradeMealy's pulse is as wide as the input makes it
P = L·Q goes high the moment L does and drops at the next edge. Slide the edge late (E) and the pulse shrinks to a sliver — a glitch pulse. Moore's P comes straight off flip-flops: one full clock, always.
TradeNothing between L and P is clocked
Press G to put a blip on L in the middle of a cycle. Neither machine's state changes — the blip is gone before the edge — but Mealy's P copies it and Moore's does not. Feeding the output logic from registered inputs instead of the raw input is a later topic: Pipelined Mealy.
