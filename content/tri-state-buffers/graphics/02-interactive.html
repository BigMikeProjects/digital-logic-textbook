Verilog
Every gate so far had two output states. A tri-state buffer adds a third: high impedance, written Z — the output is electrically disconnected from the wire. Not a 0, not a weak 1: not driving at all.
Z is not a logic value, it is the absence of one. Nothing downstream can read it as a bit. It exists so that several outputs can share one wire by taking turns.
An unselected decoder output (see Decoders) is driven to a hard 0. That is not the same thing as disconnected.
A floating input is a fault — an input reading noise. Z on an output is deliberate; Z arriving at an input means nobody is driving.

2b · three on one bus
Inside the buffer: an ordinary driver, then a transmission gate — a switch built from one NMOS and one PMOS.
ENNMOSPMOSswitchY
1ononclosedA
0offoffopenZ
The same transistors as the CMOS inverter. An NMOS closes when its gate is 1; a PMOS, with its bubble, closes when its gate is 0. Feed them EN and EN and they open and close together.
Why it takes two. An NMOS on its own passes a strong 0 but only a weak 1 — its output stops about one threshold voltage below VDD. A PMOS is the mirror image: a strong 1, a weak 0. Side by side, whichever value is passing, one of the pair passes it at full strength.
The switch does not drive. A transmission gate only connects or disconnects: it restores nothing, and it conducts in both directions. The driver in front supplies the 0 or 1; the transmission gate decides whether it reaches Y. Open the switch and Y is simply cut off — that is Z.

Shared data buses
Memory and peripherals all hang off one bus; a decoder enables exactly one to drive it during a read. Everything else sits in Z.
Bidirectional I/O pins
The classic inout pad: one physical pin drives out when enabled and reads in when not. Every microcontroller GPIO works this way — the use that is still everywhere.
Bus transceivers
Parts like the 74HC245 — a whole byte of tri-state buffers with one shared direction control.
what replaced it on-chip
Mostly a mux now
Inside a chip a multiplexer selects among drivers with no shared wire, no contention risk and cleaner timing. Tri-state lives at the boundary.
So the honest position: tri-state is still essential where wires leave the die — I/O pads, off-chip buses, anything bidirectional — and mostly retired inside it. Learn it for the pin and the bus, not as the default way to join two signals. Which is a neat closing of the section: the block that opened it, the mux, is what replaced this one.
This block's Verilog idiom: assigning 1'bz — it appears nowhere else in the course
The buffer, and three of them on one net
module tri_buf (input a, input en, output y); assign y = en ? a : 1'bz; // disabled => release the wire endmodule wire bus; // one net, three drivers tri_buf d0 (.a(a0), .en(e0), .y(bus)); tri_buf d1 (.a(a1), .en(e1), .y(bus)); tri_buf d2 (.a(a2), .en(e2), .y(bus));
A bidirectional pad
module io_pad (inout pin, input dout, input oe, output din); assign pin = oe ? dout : 1'bz; assign din = pin; // always able to read endmodule
Multiple drivers on one net is normally an error. Here it is the point, and Verilog resolves it the way hardware does:
drivers enabledbuswhat it means
exactly one0 / 1correct operation
nonezfloating — undefined, nothing may read it
two or more, agreeing0 / 1works, but by luck — still a design error
two or more, disagreeingxcontention
z means nobody is driving. x means drivers disagree, or the value is unknown. Students merge these two constantly.
!
Synthesis reality: 1'bz is only implementable where real tri-state hardware exists — I/O pads and dedicated bus structures. Write it in ordinary internal logic and the tool will reject it or quietly build a mux.
!
inout is the only port direction that may legitimately be driven and read. It still needs the oe ? … : 1'bz pattern — a plain assign pin = dout; makes the pin an output forever.
!
Comparing against z or x needs ===, not ==. One line, and it saves a debugging session.
