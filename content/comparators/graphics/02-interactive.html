A comparator takes two numbers A and B and reports their relationship — not a routed value, but a decision. Three one-hot outputs: exactly one is high.
The 1-bit comparator — the primitive

Scan from the most significant bit down. The first position where A and B differ decides the whole comparison — every lower bit is irrelevant. If no position differs, A = B.

Four XNORs decide which bits match; the AND-OR cascade finds the highest bit where they don't. The third output is free — one NOR recovers it.
Address decoding
Assert a chip-select when the address bus matches a device's base address — or falls inside its range.
Threshold detection
Trip an alarm or controller when a sensor or ADC reading crosses a setpoint — thermostats, over-current cut-offs, limit switches.
CPU branch conditions
The compare behind beq, blt, bge — the flags that decide whether the program counter jumps.
Sort & min/max networks
A compare-and-swap element is just a comparator driving a pair of muxes. Stack them and you have a sorting network.
4-bit comparator — relational operators in a combinational always block
module comp4 (input [3:0] a, b, output reg gt, eq, lt); always @(*) begin gt = 1'b0; eq = 1'b0; lt = 1'b0; // defaults first — nothing can be left un-assigned if (a > b) gt = 1'b1; else if (a < b) lt = 1'b1; else eq = 1'b1; // the three outputs stay one-hot by construction end endmodule
equality the structural way — XNOR reduction
always @(*) eq = &(a ~^ b); // bitwise XNOR, then AND-reduce — the gate diagram, in one line
⚠
Plain vectors compare as unsigned. 4'b1000 > 4'b0111 is true (8 > 7) — but read as two's complement those same bits mean −8 > 7, which is false. For signed comparison declare input signed [3:0] a, b or cast with $signed().
